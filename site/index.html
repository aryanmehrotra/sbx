A real database for every branch and AI agent.

Point psql, Playwright or your test runner at a sleeping sandbox. sbx holds the connection while it wakes, then hands it over. Written in Go: one static binary, no SDK, no account.

brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | sh
go install github.com/aryanmehrotra/sbx@latest

A single static Go binary for macOS and Linux. Needs Docker or a Kubernetes cluster; sbx doctor tells you what your machine supports.

Three ways people use it.

A database per branch

Every branch or pull request gets its own Postgres. Switch branches and the rest go back to sleep.

sbx create my-branch \
  --template postgres
eval "$(sbx env my-branch)"
PGPASSWORD=app psql -U app -d app

A copy per AI agent

Seed one database, snapshot it, and give each agent its own fork. A write in one never reaches another.

sbx snapshot my-branch seeded
sbx fork seeded agent-1
sbx fork seeded agent-2

A fixture per test run

Create, run the tests, remove it. Even when the tests fail, nothing is left behind.

sbx with test-db --template postgres \
  -- go test ./...

Built for AI agents, on your machine.

sbx speaks OpenSandbox, an open API for agent sandboxes with SDKs in five languages, and ships an MCP server so Claude Code, Cursor or Codex can create and use sandboxes as tools. For code you don't trust, --provider firecracker gives each sandbox its own kernel in a microVM.

sbx serve --osb-addr 127.0.0.1:8080 \
  --osb-pool python:3.11-slim=4 &

# hand sandboxes to your coding agent
claude mcp add sbx -- sbx mcp
from opensandbox import SandboxSync

sandbox = SandboxSync.create("python:3.11-slim")
run = sandbox.commands.run("python -c 'print(6 * 7)'")
print(run.logs.stdout[0].text)   # 42
sandbox.destroy()

Same SDK, same image: create to first command in 307 ms on sbx, 1,417 ms on OpenSandbox's own server. Its end-to-end suite runs against sbx in CI. Agent guide

How it works.

A sleeping sandbox's port belongs to sbx. The first connection is held open while the service starts, then handed over. Nothing in your code changes.
