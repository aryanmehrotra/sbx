Self-hosted sandboxes for AI agents.

A fresh microVM or container for each agent. Asleep at 0 B, awake on the first connection.

brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | sh
go install github.com/aryanmehrotra/sbx@latest

One Go binary for macOS and Linux. Needs Docker; microVMs need Linux with KVM.

What people use it for.

A fresh VM per agent

Each sandbox boots its own Firecracker microVM from the image, with its own kernel. Agents use the OpenSandbox SDKs, in five languages.

sbx serve --provider firecracker \
  --osb-addr 127.0.0.1:8080 &

Tools for your coding agent

Claude Code, Cursor or Codex create sandboxes, run commands and move files through sbx's MCP server.

claude mcp add sbx -- sbx mcp

Databases for branches and tests

A Postgres per branch that psql wakes, or one per test run that is always removed.

sbx with test-db \
  --template postgres \
  -- go test ./...

OpenSandbox's own end-to-end suite runs against sbx in CI. Agent guide · All guides

How it works.

A sleeping sandbox's port belongs to sbx. The first connection is held open while the service starts, then handed over. Nothing in your code changes.
