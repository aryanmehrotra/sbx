why it's different

Everyone scales to zero.
The question is what wakes it back.

On sbx the socket is the signal — so psql, a connection pool, Playwright or a test runner someone else wrote all wake it, unmodified. On an SDK platform, your own code has to know the sandbox is asleep and wake it first.

built for

Branches

A database per branch. Only the one you're looking at costs memory — the rest sit at 0 B.

AI agents

A throwaway backend that dies with the task. Shell commands are the whole integration — --json to parse.

CI

sbx ready blocks until it's genuinely serving. On a persistent runner the next job reuses warm, migrated state.

Fan-out

Seed one database, snapshot, then fork as many as you want. The migration runs a single time.
