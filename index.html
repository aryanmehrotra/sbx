one static binary · zero dependencies

A real database per branch,
that sleeps at 0 B.

Give every branch, task or AI agent its own real Postgres, Redis or browser — one that costs nothing while idle and wakes itself the moment anything connects.

No shared dev database that one bad migration breaks for everybody. No docker compose stack per branch eating your RAM. No sbx start to remember — opening a socket is the only signal.

Get started → ★ Star on GitHub
my-branch — sbx
$ sbx serve --idle 5m &                     # once per machine
$ sbx create my-branch --template postgres    # 492 ms, nothing on disk
$ eval "$(sbx env my-branch)"                 # exports your tools already read
$ psql -U app -d app                          # this wakes it
psql (16.2)  Type "help" for help.
app=# — served in ~1s, held not refused

Opening a socket is the whole integration. psql, a connection pool, Playwright and a test runner all wake a sandbox without knowing sbx exists — and a few idle minutes sleep it back to zero.

↯Wakes on any TCP connection

No SDK, no client library, no wrapper. Anything with a socket.

○Sleeps to 0 B

A stopped container with its volume intact. An idle sandbox costs no memory at all.

◆One committed file

sandbox.json says what a branch needs. Templates work with nothing on disk.

⎇Snapshot & fork

Seed a database once, then fork as many sandboxes from it as you want. The migration runs once.

▤Docker or Kubernetes

The same spec runs locally on docker or in a cluster. sbx doctor says what a host can do.

◱A live dashboard

sbx ui — every sandbox's cpu and memory against its limit, and a trace of where it's been.
