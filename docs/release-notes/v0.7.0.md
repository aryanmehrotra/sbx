# sbx v0.7.0 — sandboxes for AI agents: egress allow-list, checkpoint/resume, `sbx with`

Released 2026-08-21.

A sandbox can now reach only the hosts you list, stay awake while an agent works inside it, and
save and restore its running processes. `sbx with` runs a command against a throwaway sandbox
and always cleans up. There is a recipe for a self-hosted preview URL per pull request.

## Highlights

### Limit where a sandbox can connect with `egress_allow`

```json
{ "image": "python:3.12", "ports": [8000], "egress_allow": ["api.openai.com", "pypi.org"] }
```

The service reaches the listed hosts and their subdomains, and nothing else. It is enforced: the
sandbox sits on a bridge with no route out, and a filtering HTTP/CONNECT proxy on the gateway is
the only way through. The proxy is injected as `HTTP_PROXY`/`HTTPS_PROXY`, so ordinary clients
use it unchanged.

- Matching is anchored on the host boundary: `openai.com` allows `api.openai.com` and denies
  `openai.com.evil.com`.
- Proven on a real Linux host: a listed host connects, an unlisted one is denied, and dialling
  an IP directly gets "no route to host".
- Do not combine it with `egress: "deny"`, which would deny the listed hosts too.

### Keep an agent's sandbox awake with `idle`

An agent computing inside a sandbox sends nothing through its port, so the idle timer could put
it to sleep mid-task.

```json
{ "image": "ubuntu:24.04", "ports": [7777], "idle": "never" }
```

`"never"` (or `"0"`) leaves the service running until you sleep or remove it; a duration such as
`"30m"` sets a longer idle window. It still wakes on a connection. Services without the field
sleep to 0 B as before.

### Save and restore running processes with `sbx checkpoint` / `sbx resume`

A wake normally starts the service cold against a warm disk. Checkpoint keeps the process and
its memory.

```sh
sbx checkpoint agent-42 mid-thought    # dump memory and processes with CRIU, then freeze
sbx resume     agent-42 mid-thought    # restore them as they were
```

Proven end to end: a redis with all disk persistence off (`--save "" --appendonly no`) keeps an
in-memory key across `sbx resume`. The measurement is in
[DECISIONS.md](https://github.com/aryanmehrotra/sbx/blob/v0.7.0/docs/DECISIONS.md).

### Run tests against a throwaway sandbox with `sbx with`

```sh
sbx with test-db --template postgres -- go test ./...
```

Creates the sandbox, waits until it serves, runs your command with the sandbox's environment,
and always removes it afterwards: on success, on failure and on interrupt. Your command's exit
status becomes sbx's, so CI gates on it unchanged. `--keep` leaves the sandbox for debugging.

### A preview URL per pull request, self-hosted

[examples/pr-preview](https://github.com/aryanmehrotra/sbx/blob/v0.7.0/examples/pr-preview/README.md)
is a recipe: fork a golden snapshot per PR, use `sbx url` for a link that wakes the environment
when a reviewer opens it, and tear it down when the PR closes. An idle preview sleeps to 0 B.

### Also new

- `sbx sleep` and `sbx wake` park a sandbox or bring it back now, without waiting for the idle
  timer or a connection.
- The proxy relay buffer is 64 KiB, the measured optimum (benchstat against 32 KiB): about
  6.8 GB/s on loopback, so sbx is not the bottleneck for bulk transfers.
- The comparison table now lists `--isolation kata` (a microVM), CRIU checkpoint on podman and
  docker GPU passthrough as "partial" rather than "no".

## Known limitations

- **`egress_allow` needs a Linux host** in this release. It is refused elsewhere, with a reason.
  (v0.8.0 adds macOS, Docker Desktop and colima.)
- **`checkpoint`/`resume` need CRIU on a Linux host with podman.** docker's own
  checkpoint/restore is unmaintained: the dump works and the restore fails with
  `bind-mount /proc/0/ns/net …` (two upstream docker/containerd bugs, reproduced). sbx detects
  podman and routes through it. On macOS it is refused with a reason.
- Stronger isolation needs a Linux host with the matching runtime; each option refuses with a
  reason where it cannot run.
- Managed operation and years of production hours remain what hosted incumbents offer and sbx
  does not.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.7.0 sh
go install github.com/aryanmehrotra/sbx@v0.7.0
sbx doctor                        # checks this machine can run what you use
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached below with
`SHA256SUMS`; `install.sh` verifies them. Cluster activator:
`ghcr.io/aryanmehrotra/sbx-activator:v0.7.0`.

Nothing to migrate. Everything here is opt-in: two `sandbox.json` fields (`egress_allow`,
`idle`) and the `checkpoint`, `resume`, `with`, `sleep` and `wake` commands.
