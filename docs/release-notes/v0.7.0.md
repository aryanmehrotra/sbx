## Controls for the box an agent runs in — memory, ephemeral runs, a URL per PR

v0.6.0 pointed the dashboard at a deployment. **v0.7.0 turns to the box an agent works *inside***
— the sandbox can now reach only the hosts you name, stay awake while it is thinking, keep its
whole running process across a restart, live exactly as long as a test, or hand a reviewer a URL
per pull request. Each is real, each is caveated exactly as far as it is proven, and the two the
incumbents still win — managed operation and a decade of production hours — are left honestly with
them.

---

## `egress_allow` — the box reaches the hosts you name, and nothing else

Hand an agent a sandbox and the open question is where it can phone home to. `egress_allow` closes
it:

```json
{ "image": "python:3.12", "ports": [8000], "egress_allow": ["api.openai.com", "pypi.org"] }
```

The service reaches the listed hosts and their subdomains — an agent box that may call an LLM API
and its package registry, and no other address. It is **enforced, not advised**: the sandbox runs
on a no-NAT bridge with no route out at all, and a filtering HTTP/CONNECT proxy on the gateway is
the only way through — injected as `HTTP_PROXY`/`HTTPS_PROXY`, so ordinary clients use it without
knowing. A host off the list gets a refusal; a program that ignores the proxy and dials an address
directly finds no route. Proven on a real Linux host: a listed host connects, an unlisted one is
denied, and a direct-IP bypass gets "no route to host". The match is anchored on the host boundary,
so `openai.com` permits `api.openai.com` while `openai.com.evil.com` is denied. It does not combine
with `egress: "deny"`, which would deny the allowed hosts too.

## `idle: "never"` — keep a box awake while it works

Wake-on-connect and sleep-on-idle is the whole model — but an agent *computing* inside a box sends
nothing through its port, and the idle timer cannot tell a finished task from a running one.

```json
{ "image": "ubuntu:24.04", "ports": [7777], "idle": "never" }
```

`"never"` (or `"0"`) tells the reaper to leave the service alone until you sleep or remove it; a
duration like `"30m"` sets a longer window instead. So a box that is thinking, not serving, is not
swept out from under itself mid-task. It still **wakes** on a connection like everything else — this
only changes when it goes back to sleep — and every service without the field still drops to 0 B as
before.

## `sbx checkpoint` / `sbx resume` — the process, not just the disk

A wake starts a service cold against a warm disk. Checkpoint brings the *process* back.

```sh
sbx checkpoint agent-42 mid-thought    # CRIU-dump memory + processes, freeze
sbx resume     agent-42 mid-thought    # restore them exactly as they were
```

This is the one thing E2B and zeropod do that a filesystem snapshot cannot. It needs CRIU on a
Linux host, and — this is the part that took a real Linux box to learn — it needs **podman**.
docker's own checkpoint/restore is unmaintained: the dump works, the restore dies with
`bind-mount /proc/0/ns/net …` (two upstream docker/containerd bugs, reproduced). podman's CRIU
integration restores cleanly, so the provider detects a podman runtime and routes through it.

Proven end to end: a redis started `--save "" --appendonly no` (no disk persistence at all), with
a key set only in memory, comes back after `sbx resume` with the key **present**. On macOS it is
refused with a reason, because CRIU needs a Linux host. [DECISIONS.md](../DECISIONS.md) records the
measurement.

## `sbx with` — a fixture that cleans up after itself

```sh
sbx with test-db --template postgres -- go test ./...
```

Create the sandbox, wait until it serves, run the command with the sandbox's env exported, and
**always remove it afterwards** — on success, on a failing test, on an interrupt. The command's
own exit status becomes sbx's, so CI gates on it unchanged. It closes the one thing a
create/env/rm script cannot guarantee: a test that panics or a runner that is killed leaks the
sandbox and its volume. The Testcontainers shape, on sbx's terms. `--keep` leaves it for a
post-mortem.

## A URL per pull request, self-hosted

[`examples/pr-preview`](../../examples/pr-preview/) is a recipe, not a platform: fork the golden
snapshot per PR, `sbx url` for a link that wakes the environment when a reviewer opens it, tear it
down on close. The difference from the hosted preview platforms is that an idle preview here
sleeps to **0 B** instead of billing.

## Also

- **`sbx sleep` / `sbx wake`** park a sandbox now or bring it back on demand, without waiting on
  the idle timer or a client connection.
- **The proxy relay buffer is sized at the measured 64 KiB optimum** (benchstat over 32 KiB), so a
  bulk transfer moves at ~6.8 GB/s on loopback and sbx is never the bottleneck a query hits.
- The comparison matrix now reflects what sbx *does*: `--isolation kata` (a microVM), CRIU
  checkpoint on a podman runtime, and docker GPU passthrough all moved from a flat "no" to a
  caveated "partial".

## Install or upgrade

```sh
brew install aryanmehrotra/tap/sbx        # or: brew upgrade sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | sh
go install github.com/aryanmehrotra/sbx@v0.7.0
```

Binaries for macOS, Linux, FreeBSD and Windows on amd64 and arm64 are attached below with
`SHA256SUMS` beside them — `install.sh` verifies it. The cluster activator is
`ghcr.io/aryanmehrotra/sbx-activator:v0.7.0`.

**Nothing to migrate.** Everything here is new and opt-in: two `sandbox.json` fields (`egress_allow`,
`idle`) and the `checkpoint`, `resume`, `with`, `sleep` and `wake` commands; existing specs and
commands are unchanged. **The one thing to know:** `egress_allow` and stronger isolation need a
Linux host with the matching runtime, and `checkpoint`/`resume` need CRIU on a podman runtime —
each refuses with a reason where it cannot run rather than pretending it did.
