# sbx v0.15.1 — `sbx create` over an asleep sandbox no longer fails on `files`

Released 2026-09-29.

Upgrade if you re-run `sbx create` over sandboxes that may be asleep and declare `files`. Nothing
else changes: no spec field, command, flag or wake-path behaviour differs from v0.15.0.

## Before you upgrade

- Behaviour change: `sbx create` over a sandbox that already exists and is asleep leaves each
  asleep service as it is, and does not re-run its mount check, health wait or `init`. Do this:
  to re-run them, `sbx wake <sandbox>` and then `sbx create` again.

## Fixes

- `sbx create` re-run over an asleep sandbox no longer reports a `files` entry as "did not mount as a file".

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.15.1 sh
go install github.com/aryanmehrotra/sbx@v0.15.1
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.15.1`.

Full changelog: https://github.com/aryanmehrotra/sbx/compare/v0.15.0...v0.15.1
