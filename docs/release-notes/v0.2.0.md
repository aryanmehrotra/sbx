# sbx v0.2.0 — live dashboard (`sbx ui`), guided `sbx init`, Homebrew install

Released 2026-08-16.

v0.1.0 could run sandboxes but could not show you any. v0.2.0 adds `sbx ui`, a live dashboard of
every sandbox, and a guided `sbx init` for when you have none yet. It also adds `sbx history` and
a Homebrew install.

## Highlights

### See every sandbox, awake or asleep, in `sbx ui`

Every sandbox with its state, CPU and memory, and what the daemon has been doing, refreshed every
second. Arrows move, `enter` wakes, `s` sleeps, `l` reads logs, `d` removes (after asking), `q`
quits.

```sh
sbx ui
```

- `enter` wakes a service by connecting to it, the same way anything else wakes it.
- An asleep service shows a dash, not a zero: nothing is running, so there is nothing to measure.
  An awake service whose sample has not arrived yet shows a dash too.
- With no terminal (`sbx ui | grep …`) it prints the table once instead of failing.
- The update notice never slows drawing. It is checked in the background at most once a day,
  never in CI, and `SBX_NO_UPDATE_CHECK=1` turns it off.

### Start with `sbx init`

`sbx init` asks you to pick a template and writes `sandbox.json` for you. `sbx init >
sandbox.json` still works for scripts.

```sh
sbx init
```

### Find out what happened with `sbx history`

`sbx history` lists what changed and every wake and sleep, with secrets redacted. It reads a
file, so it still works when docker does not.

```sh
sbx history
```

### Help that says what to do next

`sbx <command> --help` explains one command and prints to stdout, so it can be piped. Error
messages now name the next step; for example, a failed health check names the command and its
exit code.

### Install with Homebrew

```sh
brew install aryanmehrotra/tap/sbx
```

Release binaries now build reproducibly. The release toolchain is pinned to an exact Go patch
(1.26.5), so the same tag rebuilds to the same bytes, bit for bit, from a different host OS and
architecture.

## Fixes

- With docker unreachable, the dashboard no longer shows "no sandboxes yet" beside the connection
  error. A failed listing is reported as a failure, not an empty fleet.
- The daemon's log output no longer has a ragged left edge.

## Known limitations

- Windows has no raw terminal mode here, so `sbx ui` prints the table once and says so.
- These notes were written after the release. Release notes became required in v0.3.0, and this
  one was backfilled from the commits.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.2.0 sh
go install github.com/aryanmehrotra/sbx@v0.2.0
sbx doctor                        # checks this machine can run what you use
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached below with
`SHA256SUMS`; `install.sh` verifies them. Cluster activator:
`ghcr.io/aryanmehrotra/sbx-activator:v0.2.0`.
