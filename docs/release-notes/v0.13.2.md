# sbx v0.13.2 — OpenSandbox SDK pools and e2e tests now pass against sbx

Released 2026-09-27.

**Upgrade if you drive sbx through the OpenSandbox SDKs.** sbx was stricter than upstream's own
server in two places, so upstream's `pool` and `e2e` test files failed; both now pass and are
gated in CI. Error messages no longer promise features in releases that did not ship them.
Nothing changes for `sandbox.json`, the wake path, docker, Kubernetes, or the microVM provider.

## Before you upgrade

- **Behaviour change:** a code-interpreter sandbox reports `Running` once execd answers, before
  Jupyter does. The upstream SDKs wait for Jupyter themselves.
  **Do this:** nothing if you use the SDK. If you call `/code` directly, the first call waits
  inside execd (bounded) for Jupyter to start.
- **Behaviour change:** `renew-expiration` to an earlier time that is still in the future now
  succeeds and shortens the sandbox's life. It used to be refused.
  **Do this:** only renew to the expiry you want. A renew to now or the past is still a `400`.

## Highlights

### Upstream's `pool` and `e2e` suites pass

Upstream's `tests/go` at `release-1.1.0`, unmodified, run in CI on every change:

| Check | v0.13.0 | v0.13.2 |
|---|---|---|
| v0.10.0 tier, docker | 50 passed · 0 failed · 2 skipped | same |
| v0.10.0 tier, microVMs (code_interpreter included) | 48 · 0 · 4 | same |
| `pool` (v0.11.0 tier), with a Redis | 4 passed · 8 failed · 8 skipped (not gated) | **20 passed** · gated |
| `e2e` (v0.12.0 tier), keyless | never ran | **3 passed** · gated |

- **A renew may shorten the expiry**, as upstream's server allows
  (`ensure_future_expiration`). The SDK pool renews each member to the caller's timeout, usually
  earlier; refusing that broke 8 pool tests.
- **`Running` means execd answers.** Upstream's `e2e` starts the code-interpreter image with
  `tail -f /dev/null`, so Jupyter never starts and every test timed out waiting. sbx now matches
  upstream, one step stricter: it still waits for execd. Reasoning:
  [DECISIONS.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.2/docs/DECISIONS.md)
  ("Running means usable").

### "Not implemented" errors name the feature

Nine parts of the API answered `501` saying they would arrive in v0.11.0, which shipped none of
them. They now name the missing feature and point to the roadmap: isolated sessions, server-side
pools, registry credentials, `secureAccess`, `credentialProxy`, lifecycle hooks,
renew-on-access, server-proxied endpoints and signed endpoints.

### Also

- [COMPARISON.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.2/docs/COMPARISON.md) adds agent
  sandboxes: sbx beside OpenSandbox, E2B, Daytona, Modal, Cloudflare, Vercel and isorun, and
  ComputeSDK's time-to-interactive leaderboard, each vendor figure linked to its source.
- [BENCHMARKS.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.2/docs/BENCHMARKS.md) adds the
  v0.13.0 microVM create-to-first-command figures (141 ms frozen pool, 699 ms asleep pool,
  2,821 ms cold; nested-KVM CI runner, not bare metal).

## Fixes

- `scripts/osb-conformance.sh --no-key` always started the daemon with a key, so upstream's
  `e2e` file had never run.

## Known limitations

- The rest of those upstream tiers is not built: `isolated_session` (48 tests) and
  `credential_vault` (4 tests). See
  [ROADMAP.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.2/docs/ROADMAP.md).

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.13.2 sh
go install github.com/aryanmehrotra/sbx@v0.13.2
sbx doctor                        # checks this machine can run what you use
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached below with
`SHA256SUMS`; `install.sh` verifies them. Cluster activator:
`ghcr.io/aryanmehrotra/sbx-activator:v0.13.2`.

v0.13.1 was tagged but never published: the release gate caught a flaky test
(`TestSleepAndWakeReachAScopedDaemon`, 6 failures in 900 runs, 900/900 after the fix). v0.13.2 is
v0.13.1 plus that test fix; no product code differs.
