# sbx v0.17.0 — the filter adds the real credential a sandbox never holds

Released 2026-10-15.

A sandbox can now reach an authenticated API without ever holding the credential for it. You give
the vault the real value, the sandbox gets a placeholder or nothing at all, and the egress filter
adds the credential on the way out. Upgrade if you run code you do not trust, or if you set
`egress: "deny"` on Docker Desktop or colima — that combination is now refused rather than quietly
letting traffic out.

## Before you upgrade

- Breaking: `egress: "deny"` is refused on Docker Desktop and colima, where the engine's VM routes
  the bridge out whatever masquerade says. Do this: use `egress_policy` or `egress_allow`, which
  decide there for traffic that honours `HTTP_PROXY`. For a denial at the route, run on a host whose
  docker is native.
- Behaviour change: a sandbox whose `sbx serve` restarted is told its credential vault cannot come
  back, with a 412 naming the fix, instead of being given one that signs with an authority the
  sandbox does not trust. Do this: re-create the sandbox. The vault's authority is held in memory
  only and never written to disk, so a restart cannot recover it.
- Behaviour change: a create is refused when something on the host already routes the
  `198.18.0.0/15` range sbx addresses sandbox bridges from. Do this: remove the route the refusal
  names — Clash and Surge fake-IP modes are the usual source.
- New requirement: `credentialProxy` needs a host where `sbx serve` holds the sandbox's egress
  filter itself. Do this: `sbx doctor` and read the `hosted egress filter` line.

## Highlights

- Give a sandbox a credential it never sees: `credentialProxy` on the create opts in, then POST the
  real value and its binding to the OpenSandbox Credential Vault API. The vault is write-only — the
  value goes in and never comes out — and the filter adds the header on the way to the bound host.
- `SBX_CREDENTIAL_VAULT_CA` names the authority a `credentialProxy` sandbox is given at
  `/etc/sbx/credential-vault-ca.pem`, for an entrypoint that adds it to the image's own trust store.
- `sbx doctor` reports `hosted egress filter`: whether `sbx serve` holds a sandbox's filter itself
  here, which is what `credentialProxy` needs.
- `credentialProxy` on a host that cannot hold a hosted egress filter is refused with a 400 before
  any sandbox is made, rather than creating one whose vault could never work.

## Known limitations

- The vault's authority lives in `sbx serve` memory and is never persisted. Restarting the daemon
  ends every vault it minted; those sandboxes must be re-created.
- `egress: "deny"` on a VM-backed engine is now *refused*, not made to work. The engine's VM holds
  the route, so only a native-docker host can deny at the route.
- TLS is terminated only for hosts a binding names. Everything else passes through untouched.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.17.0 sh
go install github.com/aryanmehrotra/sbx@v0.17.0
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.17.0`.
