# sbx v0.10.0 — OpenSandbox API: 14 ms creates from a warm pool, plus code interpreter, terminals and snapshots

Released 2026-09-26.

`sbx serve --osb-pool` keeps sandboxes pre-created, so an OpenSandbox `create` answers in about
14 ms. Cold creates drop from about 4 s to about 170 ms. The API gains code-interpreter contexts,
terminals, a port proxy, snapshots, templates and volumes.
This release includes every [v0.9.1](https://github.com/aryanmehrotra/sbx/blob/v0.10.0/docs/release-notes/v0.9.1.md)
security fix. If you run v0.9.0 without a key, read that first.

## Before you upgrade

- Behaviour change: `sbx rm` also removes the image's own data volumes (a redis's `/data`, a
  postgres data directory). Do this: copy out anything you need before `sbx rm`.
- Behaviour change: API sandboxes are health-checked once a minute, and quickly only while
  starting (12x fewer `docker exec` calls). Do this: nothing.

## Highlights

```sh
sbx serve --osb-addr 127.0.0.1:8080 --osb-pool python:3.11-slim=8
export OPEN_SANDBOX_API_KEY="$(cat ~/.sbx/osb/key)"
```

- A warm pool: `create` claims a pre-created sandbox with a fresh token, and the pool refills.
  A request it can't match exactly (volumes, a snapshot, a policy) takes the normal path.
- Create through first command: 13.7 ms median from the pool, 207 ms cold (`scripts/osb-bench.sh`,
  M4, colima). Details: [BENCHMARKS.md](https://github.com/aryanmehrotra/sbx/blob/v0.10.0/docs/BENCHMARKS.md).
- Code interpreter: Jupyter contexts per language, state kept between cells, rich results, interrupt.
- Terminals (PTY sessions over WebSocket), and `GetEndpoint(port)` proxying any port over HTTP and WebSocket.
- Snapshots of a running sandbox's filesystem, templates, and `pvc` and `host` volumes (`--osb-host-paths`).
- Upstream's e2e suite runs 52 tests against sbx, up from 38, and they pass. Check it:
  `scripts/osb-conformance.sh --tier v0.10.0` and `scripts/osb-usecases-e2e.sh`.

## Fixes

- `sbx mcp`: cancelling a `command_run` at the wrong moment left the command running.
- A failed pause or resume could leave a sandbox unreachable.
- A snapshot image carried the source sandbox's live token.
- A host volume path could be swapped for a symlink between the check and the mount.

## Known limitations

- Pool members are running containers: fifty python members held about 620 MiB. `--osb-pool-freeze` freezes waiting members.
- The OpenSandbox API is docker-only. Kubernetes answers `501` with the reason.
- Known issue: `sbx sleep` and `sbx wake` do not find a daemon started with `--only` (fixed in v0.13.0).
- Known issue: a sleeping sandbox with `sbx.idle=sleep` follows a host volume symlink swapped in while asleep (fixed in v0.13.0).
- Not implemented: isolated sessions, the credential vault, server-proxy mode. They answer `501`.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.10.0 sh
go install github.com/aryanmehrotra/sbx@v0.10.0
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.10.0`.
