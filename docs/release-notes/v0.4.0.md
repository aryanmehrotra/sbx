# sbx v0.4.0 — one `sbx connect` for a sandbox spread over several deployments

Released 2026-08-17.

`sbx connect` now takes several deployments at once and gives back one local port map, so a
two-service sandbox is one command again. `sbx ui` groups services into sandboxes, and scripts
get `sbx list --json`.

## Before you upgrade

- Breaking: `sbx connect` refuses a plain `http://` URL to anything but this machine, because it
  would send the token in clear text. Loopback addresses are unaffected. Do this: use the
  `https://` URL, or set `SBX_CONNECT_INSECURE=1` for a network you trust.

## Highlights

```sh
sbx connect db=https://db.example.dev cache=https://cache.example.dev
#   db     ->  127.0.0.1:5432
#   cache  ->  127.0.0.1:6379
```

- A named endpoint reads `SBX_CONNECT_TOKEN_<NAME>` before the shared `SBX_CONNECT_TOKEN`.
- Port clashes are named. Move one with `--port-offset replica=1000`.
- Deployments are fetched together, so three sleeping ones pay one cold start. If one fails, the command fails.
- In `sbx ui`, `v` folds services into one row per sandbox, with state such as `2/2 up`.
- The dashboard title shows sbx's memory and the host's free memory. `a` lists every container by memory.
- For scripts and agents: `sbx list --json`. An empty fleet is `[]`.
- New [docs/AGENTS.md](https://github.com/aryanmehrotra/sbx/blob/v0.4.0/docs/AGENTS.md): a block to paste so coding agents use a sandbox instead of `docker run`.

Walkthrough: [USE-CASES.md](https://github.com/aryanmehrotra/sbx/blob/v0.4.0/docs/USE-CASES.md).

## Fixes

- `sbx connect db=… --port-offset 1000 cache=…` silently dropped `cache`. It is now refused.
- An offset that landed on port 0 bound a random port. Offsets outside 1-65535 are refused.
- `db-1` and `db_1` silently shared `SBX_CONNECT_TOKEN_DB_1`. Now refused, naming the variable.
- A silent deployment hung `sbx connect`. The request now times out after 60 s and caps the reply at 1 MB.
- A URL containing a password was printed in full in errors. It is now redacted.
- A slow container runtime reported "context deadline exceeded". It now says docker did not answer in time.
- A five-service sandbox listed only four in the dashboard's detail block.

## Known limitations

- A container shares the host kernel. `--isolation gvisor|kata` is refused where that runtime is absent.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.4.0 sh
go install github.com/aryanmehrotra/sbx@v0.4.0
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
A single-URL `sbx connect` means what it did in v0.3.0. Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.4.0`.

Full changelog: https://github.com/aryanmehrotra/sbx/compare/v0.3.0...v0.4.0
