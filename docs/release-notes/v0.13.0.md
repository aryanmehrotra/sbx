# sbx v0.13.0 — microVMs run confined by default, and start in 141 ms from a warm pool

Released 2026-09-27.

Every Firecracker VMM now runs under Firecracker's jailer, as its own unprivileged user in its
own chroot and cgroup. `--osb-pool` works on microVMs. If a VM's network cannot be guarded, the
VM is refused instead of started. Nothing changes on docker or Kubernetes.

## Before you upgrade

- Breaking (firecracker only): a host that cannot run the jailer (no cgroup v2, no mknod) or
  guard a bridge now refuses microVM creates. Do this: run `sbx doctor`, which names the fix. To
  opt out: `SBX_FC_JAILER=off` (v0.12.0's risk, warns on every use) or `--fc-firewall=unmanaged`.
- Behaviour change: the OpenSandbox API refuses to serve on firecracker without the jailer.
  Do this: fix the jailer, or pass `--osb-insecure-no-jailer` on a development host.
- New requirement: the jailer's uid range must not contain a real account. Do this: move it with
  `SBX_FC_JAILER_UID_BASE` if it overlaps.

## Highlights

```sh
sbx doctor                # checks /dev/kvm, cgroup v2, the jailer, iptables and the bridge guards
sbx serve --provider firecracker --osb-addr 127.0.0.1:8090 --osb-pool node:22-slim=4
```

- Each VMM runs under its own uid, in a chroot holding only its own kernel, drives and devices.
- Shared kernels and read-only drives stay root-owned, so a compromised VMM cannot rewrite them.
- Sockets are checked by the peer's uid. A planted symlink is never followed.
- Create to first command from a frozen pool: 141 ms median on a GitHub-hosted runner (not bare metal).
  Details: [BENCHMARKS.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.0/docs/BENCHMARKS.md).
- Pool members wait asleep or frozen (`--osb-pool-freeze`), and get fresh credentials when claimed.
- `sbx serve --osb-addr` works through the helper VM on an M3+ Mac (unit-tested, not yet run end to end).
- Why: [DECISIONS.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.0/docs/DECISIONS.md) ("Every VMM runs under Firecracker's jailer").

## Fixes

- A daemon started with `--only` is now found by `create`, `list`, `ui`, `doctor`, `sleep` and `wake`.
- A wake refuses with `HostBindChanged` if a host path changed while the sandbox slept.

## Known limitations

- **Warning:** no network namespace per VM. A VMM escape reaches what a non-root host uid can reach.
- **Warning:** no disk quota per VM. Put `SBX_FC_STATE` on its own filesystem or enable project quotas.
- The daemon still runs as root. These three block untrusted use:
  [SECURITY.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.0/SECURITY.md).
- Each VM still copies its image's data without reflink. No pool through the helper VM, no bare-metal benchmark.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.13.0 sh
go install github.com/aryanmehrotra/sbx@v0.13.0
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.13.0`.
