# sbx v0.13.0 — microVMs run confined by default, and start in 141 ms from a warm pool

Released 2026-09-27.

Every Firecracker VMM now runs under Firecracker's jailer: as its own unprivileged user, in its
own chroot and cgroup. `--osb-pool` works on microVMs, with a median of 141 ms from `create` to
a first command from a frozen pool. If a VM's network cannot be guarded, the VM is refused instead
of started.

## Before you upgrade

- **Breaking (firecracker only):** a host that cannot run the jailer (no cgroup v2, no mknod),
  or cannot guard a bridge, now refuses microVM creates that v0.12.0 would have started.
  **Do this:** run `sbx doctor`, which names the fix. To opt out deliberately:
  `SBX_FC_JAILER=off` (brings back v0.12.0's risk exactly, warns on every use) or
  `--fc-firewall=unmanaged` (you own the host firewall).
- **Behaviour change:** the OpenSandbox API refuses to serve on firecracker without the jailer.
  **Do this:** fix the jailer, or pass `--osb-insecure-no-jailer` on a development host.
- **New requirement:** the jailer's uid range must not contain a real account; sbx does not
  check `/etc/passwd`.
  **Do this:** move the range with `SBX_FC_JAILER_UID_BASE` if it overlaps.

## Highlights

### Each microVM is confined by the jailer

- **The VMM is not root.** Each runs under its own uid from a range.
- **A chroot per VM** holds only that VM's kernel, drives, snapshot files, `/dev/kvm`,
  `/dev/net/tun`, `/dev/urandom` and sockets. The shared kernel and read-only drives stay
  root-owned, so a compromised VMM cannot rewrite them for the next sandbox.
- **Sockets are checked by the peer's uid** (`SO_PEERCRED`). A symlink planted in a jail is never
  followed; a foreign socket is refused, not read as "asleep".
- **The host guard fails closed**, and its IPv6 half is rechecked with the iptables half on every
  wake and resume.
- `sbx doctor` grades the jailer, the host firewall mode, and whether the microVM state
  directory shares `/`.

Reasoning: [DECISIONS.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.0/docs/DECISIONS.md)
("Every VMM runs under Firecracker's jailer").

### A warm pool on microVMs

```sh
sbx doctor                # checks /dev/kvm, cgroup v2, the jailer, iptables and the bridge guards
sbx serve --provider firecracker --osb-addr 127.0.0.1:8090 --osb-pool node:22-slim=4
```

Members wait asleep (snapshot on disk) or frozen (paused in memory), and each gets fresh
credentials when claimed. A claim refuses a member parked in the other jail mode. Time from
`create` to `runCommand('node -v')`, 3 rounds of 4 concurrent creates, `node:22-slim`, on a
GitHub-hosted x86_64 runner (shared CI, not bare metal):

| Mode | median | p95 |
|---|---:|---:|
| cold create | 2,821 ms | 5,769 ms |
| **warm pool, frozen** (`--osb-pool-freeze`) | **141 ms** | 207 ms |
| warm pool, asleep | 699 ms | 957 ms |

All 12 pooled creates came from the pool. A frozen claim's `create()` takes a median of about
37 ms; most of the rest is `node -v`. Design:
[the spec](https://github.com/aryanmehrotra/sbx/blob/v0.13.0/docs/superpowers/specs/2026-09-26-api-on-microvms.md).

### Also new

- **The OpenSandbox API through the helper VM** (M3+ Mac, Windows 11): `sbx serve --osb-addr`
  serves from inside the helper VM and exposes it on the host. Unit-tested, not yet run end to
  end on a Mac.

## Fixes

- A daemon started with `--only` is now found by `create`, `list`, `ui`, `doctor` and
  `sleep`/`wake` (it writes `~/.sbx/daemons/<pid>.json`). A v0.10.0 known issue.
- A wake mounts only the host directories that `create` validated. If a path changed while the
  sandbox slept (a swapped symlink), sbx refuses with `HostBindChanged`. A v0.10.0 known issue.
- Stopping a VM now signals the recorded VMM even when its command line no longer names the VM.
- A running VMM is addressed in the jail mode it was launched with.

## Known limitations

- **Warning: no network namespace per VM.** A VMM escape reaches whatever a non-root uid on the
  host's network can reach. (Added in v0.14.0.)
- **Warning: no disk quota per VM.** One sandbox, or a compromised VMM, can fill `SBX_FC_STATE`.
  Put it on its own filesystem or enable project quotas; `sbx doctor` warns when it shares `/`.
- **The daemon still runs as root**, for taps, bridges, iptables and the jailer itself.
- These three are the remaining prerequisites before anonymous or untrusted use; see
  [SECURITY.md](https://github.com/aryanmehrotra/sbx/blob/v0.13.0/SECURITY.md).
- Each VM still copies its image's data where reflink is unavailable.
- No warm pool through the helper VM (`--osb-pool` is not carried into it), and no bare-metal
  benchmark yet.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.13.0 sh
go install github.com/aryanmehrotra/sbx@v0.13.0
sbx doctor                        # checks this machine can run what you use
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached below with
`SHA256SUMS`; `install.sh` verifies them. Cluster activator:
`ghcr.io/aryanmehrotra/sbx-activator:v0.13.0`.

Nothing changes on docker or Kubernetes.
