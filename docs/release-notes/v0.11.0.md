# sbx v0.11.0 — Firecracker microVM sandboxes (Linux with KVM, Apple Silicon M3+)

Released 2026-09-26.

A new provider runs each sandbox as a Firecracker microVM, a small VM with its own guest kernel,
from the same `sandbox.json`. Sleep is a memory snapshot, so a woken sandbox keeps its processes.
It runs on Linux with `/dev/kvm`, and on M3+ Macs through a helper VM that sbx manages.

## Before you upgrade

- New requirement (microVMs only): isolation between microVMs depends on the host's `FORWARD`
  policy being `DROP`. sbx writes no firewall rules, and a guest can reach host services on
  `0.0.0.0`. Do this: run `sbx doctor`, which checks the policy.
  Details: [SECURITY.md](https://github.com/aryanmehrotra/sbx/blob/v0.11.0/SECURITY.md).
- Docker and Kubernetes sandboxes are unchanged.

## Highlights

```sh
sbx doctor                # which microVM path this machine has, and why
sbx create web --provider firecracker --template nginx
```

- Linux with `/dev/kvm` runs Firecracker directly. A Mac (M3 or later, macOS 15+) runs it in a colima helper VM.
- A connection on the Mac still wakes the sandbox. Everything else is refused, naming what to change.
- Wake from snapshot to first byte: 224 ms median on an M4 through nested virtualisation.
  Bare metal is not measured. Details: [BENCHMARKS.md](https://github.com/aryanmehrotra/sbx/blob/v0.11.0/docs/BENCHMARKS.md).
- On a Mac this is parity for development, not speed. The docker warm pool stays the fast path there.
- `sbx exec`, `sbx cp` and health checks reach the VM over vsock, a host-to-VM socket.
- A restored VM never answers with its parent's identity: it gets a fresh token before a wake is let through.

## Known limitations

- Status: Mac on M4 run by hand (16/16). lima, Windows 11 with WSL2 and Kubernetes `kata-fc`
  are not yet run end to end.
- A sleeping microVM uses disk: its memory snapshot is about its RAM, 256 MiB by default.
- Refused on microVMs: `build`, `files`, `mounts`, `init`, `gpus`, `cap_add`, `egress_allow` and
  `egress_policy`, and images whose `USER` is not root. The OpenSandbox API stays docker-backed.
- A microVM has no route out (`egress: "deny"`).
- Known issue: under heavy memory pressure a sleep can time out. The VM is then stopped and cold-boots on wake.
- Not yet: forking a microVM snapshot, the OpenSandbox API and warm pool on microVMs.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.11.0 sh
go install github.com/aryanmehrotra/sbx@v0.11.0
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.11.0`.
