# sbx v0.11.0 — Firecracker microVM sandboxes (Linux with KVM, Apple Silicon M3+)

Released 2026-09-26.

A new provider runs each sandbox as a Firecracker microVM: the same `sandbox.json`, with its own
guest kernel instead of the host's. Sleep is a memory snapshot, so a woken sandbox keeps its
memory and running processes. It runs on Linux with `/dev/kvm`, and on M3+ Macs through a helper
VM that sbx manages. Docker and Kubernetes sandboxes are unchanged.

## Before you upgrade

- **New requirement (for microVMs only):** isolation between microVMs depends on the host's
  `FORWARD` policy being `DROP`. sbx writes no firewall rules, and a guest can reach host
  services listening on `0.0.0.0`.
  **Do this:** run `sbx doctor`; it checks the policy, and `create` warns when it is not `DROP`.
  Details: [SECURITY.md](https://github.com/aryanmehrotra/sbx/blob/v0.11.0/SECURITY.md).

## Highlights

### Create a microVM sandbox

```sh
sbx doctor                # which microVM path this machine has, and why
sbx create web --provider firecracker --template nginx
```

| Host | What happens | Proven by |
|---|---|---|
| Linux with `/dev/kvm` | Firecracker directly | e2e in a Linux VM with KVM; a new CI job where the runner has `/dev/kvm` (first run: this release) |
| Mac, M3 or later, macOS 15+ | sbx runs Firecracker inside a colima helper VM; a connection on the Mac still wakes the sandbox | e2e on an M4: 16/16 |
| Mac with lima instead of colima | same design | not yet run end to end |
| Windows 11 with WSL2 | same design, in a WSL distro | built and unit-tested; not yet run on Windows |
| Kubernetes with a `kata-fc` RuntimeClass | `--isolation firecracker` | unit-tested only |
| anything else | refused, naming what to change | — |

### Sleep keeps memory; wake in about 224 ms

On an Apple M4 through nested virtualisation (helper VM 2 vCPU / 2 GiB, nginx, 12 interleaved
rounds, `scripts/fc-anywhere-e2e.sh`):

| | median | p95 |
|---|---:|---:|
| wake from snapshot to first byte | **224 ms** | 282 ms |
| request to an awake sandbox | 8.8 ms | — |
| `sbx exec` round trip | 788 ms | — |
| `sbx sleep` | 709 ms | — |
| `sbx create` | 11.5 s | — |

On a Mac this is parity for development, not speed: nested virtualisation pays for every page the
guest touches after a restore, and the v0.10.0 docker warm pool stays the fast path there.
Bare-metal Linux has not been measured; these are the only numbers this release claims. Phase
breakdown: [BENCHMARKS.md](https://github.com/aryanmehrotra/sbx/blob/v0.11.0/docs/BENCHMARKS.md).

### How it holds together

- `sbx exec`, `sbx cp` and health checks go through execd inside the VM, over vsock.
- A restored VM never answers with its parent's identity: execd is locked before every snapshot,
  and gets a fresh token and secret before a wake is let through.
- Failures fail closed: a failed sleep stops the VM; a slow VMM is an error, not "asleep".

Two independent reviews (design; correctness and security) covered this provider. Every finding
became a fix with a failing-first test, or is listed below. Background:
[ROADMAP.md](https://github.com/aryanmehrotra/sbx/blob/v0.11.0/docs/ROADMAP.md) ·
[the spike](https://github.com/aryanmehrotra/sbx/blob/v0.11.0/docs/superpowers/specs/2026-09-26-firecracker-spike.md).

## Known limitations

- **A sleeping microVM uses disk.** Its memory snapshot is roughly the VM's RAM, 256 MiB each by
  default. `sbx doctor` shows the total.
- **Refused by name on microVMs:** `build`, `files`, `mounts`, `init`, `gpus`, `cap_add`,
  `egress_allow` / `egress_policy`, and images whose `USER` is not root. The OpenSandbox API
  (`--osb-addr`) stays docker-backed.
- **No outbound network:** a microVM has no route out (`egress: "deny"`).
- **Known issue:** under heavy host memory pressure, a sleep can time out (once in 46 rounds
  here). The VM is then stopped rather than snapshotted, so it cold-boots on wake and loses what
  was only in memory.
- Not yet: forking a microVM snapshot, the OpenSandbox API and warm pool on microVMs, a
  bare-metal benchmark.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.11.0 sh
go install github.com/aryanmehrotra/sbx@v0.11.0
sbx doctor                        # checks this machine can run what you use
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached below with
`SHA256SUMS`; `install.sh` verifies them. Cluster activator:
`ghcr.io/aryanmehrotra/sbx-activator:v0.11.0`.
