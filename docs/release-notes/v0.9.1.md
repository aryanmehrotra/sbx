# sbx v0.9.1 — security fix: the OpenSandbox API now always requires a key

Released 2026-09-26.

Upgrade now if you run v0.9.0 with `sbx serve --osb-addr` and no `--osb-key`. A sandbox could
call the keyless API, read other sandboxes' tokens and run commands in them. Without `--osb-addr`
nothing is affected.

## What happened

v0.9.0 let the API run keyless on loopback, because `127.0.0.1` looked private. On colima and
Docker Desktop every container reaches the host's loopback. No host escape was possible, but
cross-sandbox takeover was. The full advisory, including what to do about sandboxes that ran
untrusted code, is in [SECURITY.md](https://github.com/aryanmehrotra/sbx/blob/v0.9.1/SECURITY.md#advisories).

## Before you upgrade

- Breaking: a key is always required. With none given, `sbx serve` writes one to `~/.sbx/osb/key`
  (mode 0600), and `sbx mcp` reads it there. Do this: give SDK clients the key, then restart `sbx serve`.
  ```sh
  sbx serve --osb-addr 127.0.0.1:8080 &
  export OPEN_SANDBOX_API_KEY="$(cat ~/.sbx/osb/key)"
  ```
  Keyless remains as `--osb-insecure-no-key`, loopback only, with a warning.
- Breaking: a non-loopback `--osb-addr` is refused. Do this: reach the API from elsewhere with
  `sbx connect` or an SSH tunnel.
- Behaviour change: API sandboxes carry an `sbx.osb` label, and a daemon not serving the API
  leaves them alone. Do this: recreate API sandboxes created by v0.9.0.

## Fixes

- A sandbox could lift its own network policy. The egress sidecar now has its own credential that never enters the container.
- After a daemon restart, a paused sandbox could be thawed before its pause was re-applied.
- `sbx sleep` and `sbx wake` on an API-paused sandbox lost its memory. They now refuse and point at the API's resume.
- A probe from inside a sandbox now gets `401` on every route, with no key and with its own token.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.9.1 sh
go install github.com/aryanmehrotra/sbx@v0.9.1
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.9.1`.
