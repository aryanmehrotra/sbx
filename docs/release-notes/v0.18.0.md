# sbx v0.18.0 — an API create gets the isolation tier it asks for, or a refusal

Released 2026-10-16.

An OpenSandbox create can ask for a stronger kernel boundary and get it: `gvisor`, `kata` or
`firecracker` through `extensions["sbx.isolation"]`, or a 400 naming what the host cannot provide.
Both API create paths used to pass the provider a plain container whatever the request carried, so
a caller who asked for more ran on the host kernel. Upgrade if you use the API or `credentialProxy`.

## Before you upgrade

- Breaking: `credentialProxy: {}` on a create is refused with 400. Do this: say
  `{"enabled": true}` or `{"enabled": false}`.
- Breaking: a credential binding applies only where exactly one binding matches. Two bindings that
  could both cover one request are refused by the `/credential-vault` call that writes them, and a
  request no binding covers answers 502 instead of reaching the host with the placeholder the
  sandbox was given. Do this: give one of the pair a host, scheme, method or path the other does
  not claim, or fold them into one. Two on the same host that name no `match.paths` always collide
  ([refusals](https://github.com/aryanmehrotra/sbx/blob/v0.18.0/docs/TROUBLESHOOTING.md#credential-vault-answers-400-about-two-bindings-covering-one-request)).
- Behaviour change: an API create carrying `extensions["sbx.isolation"]` now acts on it, where the
  key was read by nothing and the sandbox came up as a container. A tier this host cannot provide
  is refused with a 400 that names it, and no sandbox is left behind. Do this: register the runtime
  (`sbx install gvisor`, then restart the docker daemon), or drop the extension for a container.

## Highlights

- Run an API sandbox behind a user-space kernel or a VM: `extensions: {"sbx.isolation": "gvisor"}`
  on the create, and the same for `kata` and `firecracker`. Such a create is never served from the
  warm pool, because every pool member is already a container
  ([guide](https://github.com/aryanmehrotra/sbx/blob/v0.18.0/docs/GUIDES.md#stronger-isolation-with-microvms)).
- Claude Code and Codex reach a bound host through the egress filter. Both negotiate HTTP/2, and
  the credential is now added to an h2 request as well as an HTTP/1.1 one.

## Fixes

- A request inside a bound tunnel whose TLS name or authority is not the host the tunnel was opened
  to answers 421, instead of being credentialled for the wrong host.

## Known limitations

- The API's route to a tier is unit-tested: the tier reaches the provider, and a host whose daemon
  has no such runtime refuses the create. CI's `isolation` job drives the command line, so this
  route is not yet run end to end.
- Deleting a sandbox does not close its credential vault at once. The credential values and the
  authority's private key go when that sandbox's egress filter is retired, on the next discovery
  pass (`--refresh`, 15 s by default), or when `sbx serve` exits. Nothing in a vault expires.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.18.0 sh
go install github.com/aryanmehrotra/sbx@v0.18.0
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.18.0`.
