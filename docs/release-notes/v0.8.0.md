# sbx v0.8.0 — multi-service sandboxes sleep correctly; `egress_allow` works on macOS

Released 2026-08-31.

Multi-service sandboxes now sleep and wake as a stack, and `egress_allow` works on a Mac. An
agent's sandbox that only makes outbound calls counts as active, and `sbx url` works with dev
servers. Measurements and the failures found on the way are in the
[v0.8.0 engineering log](https://github.com/aryanmehrotra/sbx/blob/v0.8.0/docs/release-notes/v0.8.0-engineering.md).

## Before you upgrade

No `sandbox.json` needs editing.

- Behaviour change: `sbx url` rewrites the `Host` header to `127.0.0.1:<port>`. Do this: add
  `--host-header pass` if your service needs the public name (absolute links, an OAuth callback).
- Behaviour change: `egress_allow` no longer needs `egress: "deny"` beside it, and no longer
  refuses on a Mac. Do this: if you set `idle: "never"` only to stop a stack sleeping, remove it.

## Highlights

- Services reach each other by name (`db:6379`), not only by `sbx-<sandbox>-<service>`.
- A dependency in use no longer sleeps. A stack sleeps top-down, and one connection wakes the pair in 0.18 s.
- `egress_allow` works on macOS, Docker Desktop, colima and a remote `DOCKER_HOST`, through a filter container on the bridge.
- Calls out of an allow-listed sandbox keep it awake, so an agent calling an API is not put to sleep.
- `sbx url` works with Vite, webpack-dev-server, Rails and Django, which refused the public `Host` header.
- `cap_add` grants a named Linux capability, such as `["SYS_PTRACE"]`. There is still no `privileged` flag.
- `--front NAME=HOST:PORT` lets a deployed sbx carry a service it can route to. It widens what
  the token gates: [SECURITY.md](https://github.com/aryanmehrotra/sbx/blob/v0.8.0/SECURITY.md).
- Preview features, off until enabled (`sbx features` lists them): `SBX_FEATURES=ssh sbx ssh my-task`
  for VS Code Remote-SSH, `sbx init --from-devcontainer`, and a waiting page for a sleeping link.
- `sbx list` says when no daemon owns the addresses it prints. The audit trail records who slept or removed a sandbox.

## Fixes

- `sbx connect` cut off replies when the client closed its write side (`nc -N`, bulk loaders).
- A branching `depends_on` graph could crash the daemon, taking every sandbox's ports with it.
- A fork interrupted by `kill -9` could serve the wrong data.
- `sbx create` was broken on Kubernetes, and `sbx url --via ssh` refused to run.
- `sbx list | grep -q` exited 141 (SIGPIPE).
- A refused `egress_allow` left a half-built sandbox that nothing could clean up.
- The test suite did not compile on Windows. All eight targets now build and vet.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.8.0 sh
go install github.com/aryanmehrotra/sbx@v0.8.0
sbx doctor
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached with `SHA256SUMS`.
Cluster activator: `ghcr.io/aryanmehrotra/sbx-activator:v0.8.0`.
