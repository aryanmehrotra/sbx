# sbx v0.8.0 — multi-service sandboxes sleep correctly; `egress_allow` works on macOS

Released 2026-08-31.

If you have been holding a stack open with `idle: "never"` because sleeping it broke things, or
gave up on `egress_allow` because your Mac refused it, both are fixed. An agent's sandbox that
only makes outbound calls now counts as active, and `sbx url` works with dev servers.

Every number below is from a live run. The
[v0.8.0 engineering log](https://github.com/aryanmehrotra/sbx/blob/v0.8.0/docs/release-notes/v0.8.0-engineering.md)
has the measurements, the failures found on the way, and what each fix cost.

## Before you upgrade

No `sandbox.json` needs editing. Two behaviours differ:

- **Behaviour change:** `sbx url` rewrites the `Host` header to `127.0.0.1:<port>` by default.
  **Do this:** add `--host-header pass` if your service needs the public name (absolute links,
  an OAuth callback).
- **Behaviour change:** `egress_allow` no longer needs `egress: "deny"` beside it, and no longer
  refuses on a Mac.
  **Do this:** nothing. If you set `idle: "never"` on a stack only to stop it sleeping, remove it.

## Highlights

### A stack sleeps and wakes as a stack

- **Services reach each other by name.** A dependent configured with `db:6379` failed with `no
  such host`, because docker's DNS knew only `sbx-<sandbox>-<service>`. Measured with a
  dependent dialling once a second: ok=0 failed=23 before, ok=20 failed=0 after.
- **A dependency in use no longer sleeps.** Its idle clock used to run out under constant load
  (at t=90s: ok=94 failed=12, and growing by 4 every 15 s). A stack now sleeps top-down, still
  reaches 0 B, and one connection brings the pair back in 0.18 s.

### `egress_allow` on macOS, Docker Desktop, colima and remote `DOCKER_HOST`

On those setups the bridge gateway is inside a VM the daemon cannot reach. sbx now runs the same
filter as a small container on the bridge, built from sbx's own source. Measured from inside a
sandbox on a Mac:

| Request | Result |
|---|---|
| a host on the list | the page |
| a host not on the list | `403`, from the filter |
| the same fetch with `HTTP_PROXY` unset | timed out — no route at all |

The workload still has no route out of its own.

### Outbound calls count as activity

An agent that reads files, compiles and calls an API looked idle to a proxy that counts inbound
bytes. Calls out of an allow-listed sandbox now keep it awake.

```json
{ "image": "python:3.12", "ports": [7777],
  "egress_allow": ["api.anthropic.com", "pypi.org"], "idle": "10m" }
```

Verified: awake through twelve consecutive 30-second idle windows while calling out, while a plain
service beside it slept on schedule at 60 s. A four-minute streaming response keeps it awake four
minutes. Cost: 2.3 ns per 32 KiB, zero allocations.

### `sbx url` works with Vite, webpack-dev-server, Rails and Django

These dev servers refused a tunnelled request (`403`) because of the public `Host` header. The
service now receives `Host: 127.0.0.1:<port>`. cloudflared's metrics listener also no longer
takes port 20241, inside sbx's own range.

### Opt-in previews behind feature gates

Each is off until you enable it; `sbx features` lists what this build has.

```sh
SBX_FEATURES=ssh sbx ssh my-task
```

- **`sbx ssh`**: open a sandbox in VS Code Remote-SSH, Cursor or JetBrains Gateway. The SSH
  connection wakes it; a sleeping sandbox woken by `ssh-keyscan` in 0.255 s.
- **`sbx init --from-devcontainer`**: a spec from the repo's `devcontainer.json`. Anything it
  cannot translate is printed on stderr.
- **A waiting page**: a browser opening a sleeping link sees what is starting instead of a blank
  page. Only after one second, only for HTTP, and it never delays the wake (503 with the page at
  1.00 s, then 200 in 1.5 ms on reload).

### Also new

- **`cap_add`** grants a named Linux capability, e.g. `["SYS_PTRACE"]`. There is still no
  `privileged` flag.
- **`--front NAME=HOST:PORT`** lets a deployed sbx carry a service it can route to, such as a
  managed database on a private address. It widens what the connect token gates; see
  [SECURITY.md](https://github.com/aryanmehrotra/sbx/blob/v0.8.0/SECURITY.md).
- `sbx list` says when no daemon owns the addresses it prints.
- The audit trail records who slept or removed a sandbox.

## Fixes

- `sbx connect` cut off replies when the client closed its write side (`nc -N`, bulk loaders).
- A branching `depends_on` graph could crash the daemon, taking every sandbox's ports with it.
- A fork interrupted by `kill -9` could serve the wrong data.
- `sbx create` was broken on Kubernetes, and `sbx url --via ssh` refused to run.
- `sbx list | grep -q` exited 141 (SIGPIPE).
- `sbx ui` went stale and misreported a cluster.
- A refused `egress_allow` left a half-built sandbox that nothing could clean up.
- The test suite did not compile on Windows; all eight targets now build and vet.

## Upgrade

```sh
brew upgrade sbx                  # first install: brew install aryanmehrotra/tap/sbx
curl -fsSL https://raw.githubusercontent.com/aryanmehrotra/sbx/main/scripts/install.sh | VERSION=v0.8.0 sh
go install github.com/aryanmehrotra/sbx@v0.8.0
sbx doctor                        # checks this machine can run what you use
```

Binaries for macOS, Linux, FreeBSD and Windows (amd64, arm64) are attached below with
`SHA256SUMS`; `install.sh` verifies them. Cluster activator:
`ghcr.io/aryanmehrotra/sbx-activator:v0.8.0`.
